# Technical changelog

Internal record of how Hussla was built, newest first. Every entry says **what** changed and **why**.

- User-facing notes: [`CHANGELOG.md`](CHANGELOG.md). Same version numbers; this file is the engineering view behind them.

## Conventions

- **Bullet shape:** `- **Short title.** What changed. *Why:* reason. ([#PR](…), \`sha\`)`
- ***(inferred)*** — the why came from the diff, docs, or code, not a stated reason. No tag means the commit, PR, or plan says it.
- **Refs:** PR link when the commit came through one; short SHAs always (max 3, then "…").
- **Sections, in order (empty ones omitted):** Architecture & backend · Data & migrations · API & contracts · Auth & security · Web client · Native · Infra & deploy · CI & tooling · Testing · Dependencies · Docs & process · Incidents & reverts.
- **New work:** add bullets under `[Unreleased — dev only]`. When `dev` ships to `main`, move them to `[Unreleased — on main]`. When a version is cut in `CHANGELOG.md`, rename the heading to match.
- **Other agents (Cursor, Codex …):** tag what you add `— *Cursor*` / `— *Codex*`. Correct a wrong entry in place; never add a second bullet that contradicts it. Only add what a commit, PR, plan, or file backs; mark anything else *(inferred)*.

### API & contracts

The contract gains setup, sign-in, passkey and step-up routes and a `X-Hussla-Step-Up` parameter; `TestRoutesMatchTheContract` fails a route served but undocumented or the reverse. `TestPrototypeAgentExamples` replays all 13 curls of the prototype guide; `TestGracefulShutdownAndRestart` (an upload in flight at SIGTERM completes; proved by swapping `Shutdown` for `Close`) and `TestSecondProcessRefused` cover the process. *Why:* Phase 3 of `docs/plans/hussla-v1.md`.
- **First-run fixes for headless servers (review items 3, 6, 11, 12, 13, 19).** The tailnet join retries with backoff (`config.TailnetRetryFirst`/`TailnetRetryMax`) instead of stopping, logs one line naming the admin DNS page when HTTPS certificates or MagicDNS are off, logs tsnet's login link once per new link, and exposes its phase and link as `auth.TailnetState`. The setup code is stored as a hash (stable across restarts, reminded not reprinted), spent by the first stored passkey rather than the claim, and wrong guesses lock out the guessing tailnet user (`config.SetupCodeLockout`) instead of replacing the code. A `HUSSLA_OWNER_LOGIN` that doesn't match the node's owner is logged with both logins. *Why:* `docs/decisions/0013-setup-code-until-a-passkey-and-tailnet-retry.md`.

- **Phase 1 security model: field provenance, approval versions, fixed-width time.** Patches name their writer; jobs, companies and answers track the last writer per field, and an agent patch that would clear or overwrite an owner-written field is refused whole with the field names (rapid property: no agent patch changes an owner-written field). Patch results keep the prior record and changed names for the activity log. - **Phase 1: Go domain, knobs, and the API contract.** `internal/domain`: jobs, companies, contacts, reviews, answers, events and the outbox email state machine; three-state patch fields (`Field[T]`: absent, set, null) with `followup` merging by key and unlisted top-level fields kept as extras; send pacing `CanSendNow` (local window, daily cap, minimum gap plus jitter, DST-safe); bare-address parsing; markdown-to-plain for email bodies. ### Auth & security

- **Identity from the connection, setup code, passkey step-up per action.** Tailnet: `WhoIs`; local: a hashed session cookie from `hussla open`'s one-time 0600 token; no header is ever read for identity. A bearer key decides alone (401, never a fall-back). Host allow-list (421) and Origin allow-list; an owner write needs the server's own Origin (replaces the contract's `X-Hussla` header). The setup code (Crockford base32, 5 tries, single use, log only) claims a tagged node and registers each address's first passkey; an ineligible caller is refused before the code is touched. Owner-only actions take a one-use WebAuthn step-up token bound to caller, method and path, 2 minutes. `internal/httpapi/auth_matrix_test.go` holds a test per plan row (no identity, non-owner and tagged peers, identity headers, key plus owner identity, no passkey tap, Host, Origin, sign-in token, before enrollment, stale approve); each of 30 checks was removed once and its test failed, except `requireOwner`'s agent branch alone, which the use-cases' own owner checks back up (removing both fails). Tests use a hand-rolled virtual authenticator (`internal/testsupport/virtualauthn`) against the real go-webauthn checks, and a fake tailnet. *Why:* `docs/decisions/0011-connection-identity-and-passkey-step-up.md`.

- **command-guard fails closed to ask, within a work budget.** A command line over 64k characters asks before it is parsed, and a read over 250 ms asks (`MAX_COMMAND_CHARS`, `MAX_EVALUATE_MS`). An exception inside the guard asks and names the error: in `evaluate()`, and in the hook's entry point for both hosts, which used to allow. The round-2 quadratics are linear now, so ordinary big heredocs still pass without asking: a pipeline's printed words are built once per pipeline (20k-shell pipeline: 10 s → ~0.2 s), `asAssigned()` makes one pass, and the IaC line checks read the line once. Also covered: brace expansion and xargs/parallel placeholder verbs ask; `function`/`coproc` bodies, `source /dev/stdin`, `bash <(…)`, `< <(…)`, `>(sh)`, stdin fed through ssh/su/xargs command strings, aliases on the line, and the wrappers chrt, taskset, pkexec, setpriv, gosu, fakeroot, nsenter, runuser, sg, strace, hyperfine, trap, `git submodule foreach|rebase -x|bisect run`, terramate run, ash/mksh/fish --command/pwsh; cdk/cdktf deploys, gcloud `deploy …` and storage mv/rsync deletes, `az storage remove|sync`, bq's verb after unknown flags, and destructive SQL through bq/Spanner/RDS Data/Athena. Git and project rules now read inside substitutions. Fixed false positives: `git apply x && $HOME/bin/check`, `aws s3 rb help`. An exemption no longer lifts after a `cd`/`pushd` on the same line. **Watchdog (round 3):** the hook entry runs its whole evaluation (branch lookups, rule files, `evaluate()`) under a preemptive 3 s watchdog (`WATCHDOG_MS`, vm's `timeout`), which stops a loop that never calls `tick()` or a rule pattern that backtracks and asks, naming the watchdog; before, either ran into the host's 10 s timeout and let the command run. Not a `worker_threads` worker: one costs ~50 ms to start on every command (hook median 65 → 160 ms measured), and exit waits for a worker blocked in a system call; with vm, an everyday command's hook stays within +10 ms. Blocking calls bound themselves: `git rev-parse` branch lookups time out at 1 s (a repo whose `.git/HEAD` is a FIFO hung the hook forever), run only for a push or commit that needs the branch, once per directory, with a clock read after each (`cd .;` + 5000 commands made 593 lookups and took 3 s); a rule file that isn't a regular file is broken. `evaluate()` forwards every option to the line evaluator and nested lines (for PR #21's lookups). The span scanners cap their nesting (256) and ask by design instead of overflowing the stack. Also read: `docker`/`podman` `exec` and `compose exec|run`, `kubectl exec … --`, `bunx`, `dotenvx run --`, `envchain`, `sops exec-env`, `firejail`, `proxychains`, `torsocks`, `watchexec`, `entr` (and `-s`), `fd -x/-X`, `gdb --args`, `GIT_SSH_COMMAND=` and `git -c core.sshCommand=`; any other program given an IaC CLI word followed by an apply/destroy/state verb asks (echo, grep, git, cat… exempt; the everyday corpus stays silent; round 4: image references with a `:tag` or `@digest`, the `opentofu/opentofu` image, and a compose service named for its image, as in `compose run terraform apply`); and deletes through azcopy, rclone (purge/delete/sync/move from a remote), s5cmd, mc, s3cmd, `az rest --method delete`, doctl, fly, and heroku. - **Project and pack rules for command-guard.** The guard loads an optional `command-guard.project.json` (deny, ask, and exact-command exemptions) and pack files in `scripts/command-guard.d/` (deny and ask).
